# ARTITRADE 새 PAPER 원장 초기화 준비 (v106, 소스 전용)

작성: 2026-11-18
상태: **초기화 기능 소스 작성 및 임시 원장 시험 통과 / APK 미생성 / 실기기 데이터 미삭제**

## 목적

기존에 뒤섞인 2026-11-14 원장, PAPER 보유·체결 기록, 전략별 연구·가상연구 결과를 다음 실험의 기준에서 제외하고, 모든 전략이 새로운 원장에 독립적으로 처음부터 기록하도록 함. 매매조건, 서명, 패키지명, 8개 전략의 계산·판정·서비스 구조는 그대로 보존함.

## 초기화 대상 (휴대전화 ARTITRADE_PHONE_MAIN_V070 내부)

- 주식 기준봉·MA·CW·GMO·마켓트렌드의 PAPER 주문/체결/포지션/연구 DB
- 코인 일반·MA·마켓트렌드의 PAPER 주문/체결/포지션/연구 DB
- 공통 시장점수, 보유중 추적, 예지·실험·추적, 실행근거 SQLite 및 JSON
- 과거 PC 원장 재승계로 남은 `.pre_pc_import_*` 및 `.pre_close_repair_*` 로컬 복제본
- Android에서 원장처럼 보일 수 있는 오래된 화면 스냅샷, 수동매도 결과, 기존 UUID 내역 캐시, 과거 원장 자동승계 기록
- 종전 PC 실시간 원장 연동은 새 에포크에서 비활성화

초기화 후에는 기존 저장 계좌를 고쳐 쓰거나 임의의 과거 체결을 복원하지 않고, 각 전략이 신규 SQLite 및 잔고 설정을 만드는 원래 생성 과정을 그대로 이용함.

## 절대 보존

- 소스 전략, 매수/매도 기준, 분할청산 규칙 및 종목조회/연결기능
- Android 패키지명, 서명, 실행권한, 키움/업비트 API 계정·인증정보
- 운용시드와 최대 보유종목 설정 `ANDROID_OPERATION_V074.json`
- 기존 사용자가 별도로 보관하고 있는 11/18 오류이력 ZIP 8개 (앱 외부 파일)
- 증명된 실거래/LIVE 주문·체결 기록: 발견 시 전체 초기화 **중단**, 자동삭제 금지

## 재유입 차단

기존 `LegacyLedgerMigration.importIfReady()`는 PC에 오래된 ZIP이 있으면 앱 시작 시 내려받아 덮어쓸 수 있으므로, 확인된 새 에포크 마커가 있으면 HTTP 확인·기존 CLOSE 경로 복구·누락 연구자료 보충 모두 건너뜀.

`UnifiedTradingService.checkPendingPCArchive()` 와 수동 PC 적용도 새 에포크가 존재하면 차단함. 앱 내 자동 PC 연구자료 보충 및 PC 동기화의 종전 데이터 반영 금지. 기존 MSERVER 서버 자체 파일 삭제는 이 소스 단계에서 수행하지 않음.

## 안전한 실행 조건

`fresh_epoch_reset_v106.py`는 함수만 제공하며 앱 시작과 연결되어 있지 않음. 다음 배포에서도 사용자가 새 에포크 초기화를 명시적으로 승인한 경우에만, 엔진 완전 중지 및 LIVE 비활성화 검증 뒤 실행해야 함.

- `preview(root)`: 삭제 예정 경로/용량 조회만 수행
- `reset(root, confirmation=CONFIRM, engine_stopped=True, live_orders_disarmed=True)`: 명시적으로 승인된 **오프라인** 로컬 PAPER 초기화만 수행
- 우연히 이 모듈을 import하거나 배포한다고 해서 실행되지 않음.
- 이 작업은 GitHub 파일만 변경했으므로 **현재 휴대전화에서 삭제된 데이터는 0개**임.
- 실행 중단 시 `PREPARING` 마커로 전체 엔진 시작 및 PC 재승계를 차단; 완료 시 `COMMITTED` 마커로 기동 허용.
- `COMMITTED` 이후 재실행 시 새로 누적한 체결이력을 삭제하지 않음.

- DB 손상 시 삭제 차단

Android 실제 사용자 원장과 실기기 초기화는 아직 미실시. APK 빌드·릴리스는 만들지 않음.
