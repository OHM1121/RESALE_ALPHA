# 0.0.2 개발 소스: MSERVER 일일 원본 PAPER 백업·사고복구 검증 설계

## 정확한 동작
- 주식: KST 정규 거래일 기준 매일 **20:10**. 한국거래소 휴장일/주말 제외. 원칙상 2026/2027 확정·정의된 거래일 달력만 허용하고 미확인 연도 달력에는 실패로 알림.
- 코인: KST 매일 **11:30**. 주말·휴일에도 수행.
- 지정시각 기기 전원 꺼짐: 다시 켜져 ARTITRADE 전략 서비스가 작동한 후 엔진 준비·마커 COMMITTED·원장 역행 검증·MSERVER 통신 인증 상태를 확인하고, 부팅 이후 최소 90초 경과시 누락된 **가장 최근 백업 대상일**을 재시도. 그 시점 실물 원장을 백업하며, 실제 캡처 시각은 ZIP 메타에 별도 기록함. 실제 과거 시각의 데이터로 소급 복원/조작하지 않음.
- 진행시간에 기기/통신이 끊기면 원본 매매원장은 그대로 두고, 저장된 해시와 일치하는 기존 임시 ZIP을 재사용해서 서버의 수신한 다음 chunk부터 재시도. 한 일자·시장당 동일 백업만 확정되며 내용이 다른 두 ZIP을 덮어쓰기 불가.
- 이력은 주식·코인 각 최신 및 날짜별 보유. 원장 구조는 기존 실제 SQLite+WAL을 `sqlite3.backup`으로 안전 복제한 ZIP. AI 연구·오류·체결근거 글로벌 DB는 허용된 소스만 포함하며 API 키/접속토큰은 미포함.
- MSERVER는 **별도 앱**임. `HubServer`에 `/v1/daily/begin/chunk/commit/latest` 및 읽기전용 다운로드 경로 추가, `DailyBackupStoreV003` 내부에 Android Keystore 암호화와 SHA-256 다중 검증. 거래앱은 `LocalHubClient.daily*` 인증요청, 256KiB 청크로 업로드. 전체 ZIP SHA 검증 + 서버 재조회 일치 확인 후에만 그날 완료 상태 기록.
- **재해복구:** 새 모듈 `DailyRecoveryV003`는 서버의 가장 최근 완전 확정 ZIP을 승인 요청에 따라 `cache/daily_recovery_quarantine_v003/`에 **검증 목적으로만** 다운로드하고 SHA/manifest/원장 파일구성을 검증함. 현재 거래 원장에 이 ZIP을 자동 적용하거나 기존 DB를 덮어쓰지 않음.
- 복구본을 현재 계좌에 실제 적용하는 단계는 아직 제공하지 않음. 마지막 백업 이후의 매수·매도 이력이 사라질 수 있으므로 기존 엔진 종료·LIVE 상태 OFF·원장 재시작 전 차단·최종 체결 비교·명시적 확인·분리된 검증 및 기존 DB 격리가 반드시 추가되어야 함. 자동 덮어쓰기 기능을 즉흥적으로 추가하면 사용자가 이전에 겪었던 원장 역행을 재현할 위험이 있음.

## 중요 한계
1. 출시된 0.0.1 앱과 현재 설치된 구형 MSERVER에는 이 백업 API가 없음. **0.0.2 거래앱 및 새 MSERVER 각각 빌드·설치 후** 활성화 가능. 현재는 source-only, APK/Release 미생성.
2. MSERVER가 거래폰과 **같은 물리적 기기**에서 실행된다면, 한 기기 파손/분실·기기 데이터 전체 초기화에는 두 원장이 같이 사라질 수 있음. 이 재해까지 대비하려면 MSERVER 데이터의 기기 외부 암호화 복제 정책 별도로 필요.
3. 실제 Android 단말에서 양 앱 인증, 연속 chunk 전송, 절전 중 재개, 원장 전체 복원 후 8전략 보유/체결 연결 검증은 미실시. CI는 가짜 SQLite ZIP·부팅시각·네트워크 계약/소스 컴파일만 검증함.
