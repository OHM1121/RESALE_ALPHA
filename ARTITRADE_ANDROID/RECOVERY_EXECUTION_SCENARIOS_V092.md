# ARTITRADE v0.9.2 — 주식·코인 8전략 공통 매수·매도 복구 시나리오

적용 대상: 주식 **기준봉 / MA / 종가베팅 / 수급매매 / 마켓트렌드**, 코인 **일반 / MA / 마켓트렌드**. 현재 배포 계열은 실거래소 시세를 이용하는 **PAPER 가상매매 전용**이다. 기존 8개 원본 원장의 매수·매도 기준, 수수료·세금·수량·목표·체결 내역의 권한은 각 원본 엔진에만 있으며, 공통 컨트롤러는 실제 체결을 임의로 생성할 수 없다.

## 복구 상태 머신 — 모든 전략 공통

```text
앱/서비스 시작 -> 원본 SQLite 무결성/미확정 주문 확인
  |
  +-- 비가동/인터넷 장애 ------------------> STOPPED / NETWORK_OFFLINE
  |        기존 수량·목표·주문증거 그대로 보존 / 추가 체결 생성 금지
  |        Android foreground service 재기동 및 OS 네트워크 회복 대기
  |
  +-- 거래소/구독 장애 --------------------> BROKER_FEED_DOWN / HELD_NOT_SUBSCRIBED
  |        원본 토큰/WS 재연결, 신규 REG 확인, 보유종목 우선 재구독
  |        REST는 과거 공식 봉 검증/보완용. 구 REST 표시가로 체결 불가
  |
  +-- 누락 기준봉/1분봉/타임프레임 ----------> CANDLE_GAP_EXIT_FIRST
  |        원본의 거래소별 시간과 종가확정 판단 후 공식 OHLCV 보완
  |        새 진입·RSI 등 봉 의존 결정만 보류
  |        독립된 가격/호가 조건의 보유 손절·익절은 NEW 현재시세로 우선 실행
  |
  +-- 현재 실제 체결/호가 부족 --------------> NO_FRESH_EXIT_EVIDENCE
  |        보유종목 신규 WS 이벤트/현재 매수호가·잔량 확인
  |        수신 시간과 거래소 시각, 종목코드, 거래소, 3초 유효기간 확인
  |
  +-- 재시작 후 신규 유효시세 ----------------> RESTART_CATCH_UP
  |        ① 원본 BUY/SELL/잔량/정책단계 복원
  |        ② 미확정 주문은 UUID/거래소 응답 재조회, 중복 실행 차단
  |        ③ 보유종목 매도 조건 먼저, 1·2차는 실제 SELL행 확인 후 다음 단계
  |        ④ 이후에도 유효한 기존 매수대기만 최신 가격으로 재판단
  |
  +-- 완전 정상 ----------------------------> LIVE_VERIFIED
           보유 손절→기존 단계 익절→기존 매수대기→신규신호→연구 순
           원본 엔진만 BUY/SELL 기록, 실행 결과 대조 후 완료 표시
```

## 적용 코드와 검증 규칙

- `unified_recovery_v092.py`: 8개 전략별 상태·증거·후속조치를 하나의 결정표로 분류함. 실제 BUY/SELL는 하지 않으며 새로운 API 요청도 만들지 않음.
- `HeldFirstQueue`: 기본 주식 틱 처리 큐에서 보유종목을 신규 후보보다 우선 처리함. 원래 시각/순서/원장을 변경하지 않으며 위험틱이 대기 중 낡지 않도록 우선순위만 변경함. 기존 3초 시세 신선도 규칙 유지.
- `recovery_scenarios_v092.json`: 별도 원본 원장과 분리된 최근 상태 파일. 이전 실행의 마지막 시각과 연결 복귀 판정을 저장하며, 기존 체결 이력을 수정하지 않음.
- 앱 UI: 각 전략 화면 상단에서 현재 복구 시나리오를 표시하며, 세로·가로 상단 ARTITRADE 바로 옆에 설치된 실제 APK 버전을 표시함.

정상/네트워크 중단/WS 끊김/구독 누락/장외/분봉 누락/재시작/원장 미확정/시세 무효에 대한 자동 시험, 주식·코인 8개 원장 보존 시험, Android 15 실제 가로↔세로 회전·기존 서명 검증을 모두 통과해야 배포함.

### 이 배포 범위의 한계

1. 휴대전화 완전 종료 상태에서는 PAPER 주문을 실제로 실행할 프로세스가 존재하지 않으므로 그 시각의 체결은 원천적으로 불가능함. 장치와 무관하게 항상 실행하려면 사용자 동의에 따른 별도 상시 가동 서버와 단일 실행권한·원장 동기화 체계가 필요함. 이를 설치하지 않고 '폰 꺼져도 실시간 체결'이라고 주장하지 않음.
2. 공식 과거 1분봉의 고가/저가가 목표에 닿았다고 해도 매수호가 잔량·호가에 따른 실제 체결 증거가 되지 않음. 과거 도달을 성과분석에 기록할 수 있지만 과거 시점에 존재하지 않은 원본 SELL행을 임의로 생성하지 않음.
3. 이 버전은 공통 체결 진입 전 시나리오 분류·보유 우선 큐를 보강하는 것이며, 각 전략의 기존 진입·목표·손절 수식은 변경하지 않음. 구체적 폰 오류이력 4개 ZIP을 실기기 수준에서 판독한 것은 아님.
