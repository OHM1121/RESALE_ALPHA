# ARTITRADE v0.7.54 — 독립 마켓트렌드 전략 설계

> 2026-11-15 사용자 요구 기반. 이 문서는 신규 설계이며, 기존 매매조건·원장에 대한 무조건적인 변경 승인으로 확대 해석하지 않는다.
> 기준 소스: 실제 v0.7.53 배포제품 커밋 `0423bcea7fb967889d87d8d961cfd055aaab9a70`. 개발 브랜치 HEAD `7e44aafe7d366ac6c8aa74b4ddf2712d8c71d40b`는 이후 회귀시험/에뮬레이터 설정을 포함.

## 1. 목표

주식/코인 각각에서 마켓트렌드(RSI20)를 기준봉(AT/general)·MA의 시장점수 음수 시 대체 진입모드가 아닌 **독립적인 상시 감시·자동매매 전략**으로 구성한다.

- 주식 탭: 기준봉 / MA / 종가베팅 / 수급매매 / 마켓트렌드
- 코인 탭: 기준봉 / MA / 마켓트렌드
- 시장점수가 좋거나 나쁘더라도 기존 기준봉·MA의 진입모드를 마켓트렌드로 전환하지 않는다. 원본 전략의 원래 시장안전 조건과 주문권한은 그대로 둔다.
- 신규 마켓트렌드 전용 원장과 시드를 기존 AT·MA 원장/잔액에서 분리한다.
- 동일 공개 시세·호가·실시간 소켓을 재사용한다. 두 번째 증권/거래소 주문 세션 생성 금지.
- 기존 `market_trend_v043.sqlite3`의 투자/연구 데이터와 이미 보유 중인 `TREND_OPEN` 거래는 종전 소속 장부에서 안전하게 종결한다.
- PC MSERVER, 앱 패키지 `com.artitrade.unified.s21dex`, 기존 서명, 데이터/사용자 설정, 원본 거래원장 유지.

## 2. 구현 대안

A. 별도 UI만 추가하고 AT/MA 지갑을 재사용: 구현 범위는 작으나 독립시드가 아니므로 제외.
B. **선택: 기존 RSI20 계산/시장데이터/청산 관리 로직을 활용하되 새 전용 전략 원장·계좌·설정·조회 화면을 분리.** 기존 모듈을 재사용하여 중복 스트림/주문을 방지하고 운영 위험을 낮춘다.
C. 완전히 새 거래소 연결/매매 엔진: 소켓 중복·레이트리밋·원장 복잡성 증가로 제외.

## 3. 운영자금 제안

- `stock.trend` / `coin.trend` 각각 5m·30m·60m·day의 독립 시간봉 계좌 네 개, 기본 각 2,000,000원/4종목(기존 기본값을 재사용하는 초기값 제안, 기존 설정 덮어쓰기 금지).
- 시간봉 5m/30m/60m/day별로 **독립 운용시드, 독립 잔액, 최대 보유종목 수**를 관리함(사용자가 2026-11-15 명시 승인). 각 시간봉의 초기 제안값은 2,000,000원/최대 4종목이며 앱의 운영설정에서 개별 수정 가능. 매수·매도는 해당 시간봉 원장/잔액에만 반영하고 같은 시장의 다른 시간봉 자금을 전용하지 않음.
- 기존 AT, MA, CLOSE, GMO, coin BASE 자금·손익·최대보유 설정은 불변.
- 새 DB 예: `stock/trend/market_trend_wallet_v054.sqlite3`, `coin/trend/market_trend_wallet_v054.sqlite3`; 계좌키 `tf`로 구분되는 `accounts(tf,seed,cash,max_positions,...)`, `positions`, `executions`, `allocations`, `reservation_audit` 보유. 기존 v043 연구 DB는 읽기 유지, 필요시 v054 전용 watch 테이블로 증분.
- 독립시드는 앱 내부의 계좌별 전략 운용한도이며, 키움/업비트 실계좌의 실물 현금을 법적·물리적으로 분리한 별도 계좌가 아님. LIVE에서는 전역 브로커 잔고/예약과 대조하고 부족 시 주문 중단.
- 새 전략은 기존 LIVE 스위치를 상속해 예기치 않게 실주문하지 않도록 **별도 명시적 LIVE 활성화**가 있기 전까지 PAPER 작동. 사용자의 현재 시장별 LIVE 설정은 그대로 보존.

## 4. RSI20 관측/매수대기/매수

- 대상: 현재 코인 거래대금 상위 40종목, 주식 기준 상위 50종목과 기존 허용 종목. 기존 위험/유동성/미관측/재진입 차단은 유지.
- 자료: 동일한 실시간 시세/호가와 5m·30m·60m·day 완성봉. RSI는 기존 Wilder(20)과 실시간 진행봉을 구분.
- `RSI <= 40`: **내부 감시·시험 전용**. 조회/연구 증거 기록 가능하나 매수대기/매수/가상매수/후속고가를 생성하지 않음.
- `RSI <= 35`: 해당 `market/symbol/frame/bar_end`에 대해 화면의 별도 `RSI 매수대기`에 표시(실주문이 아니라 관측 상태). 숫자 35.0 포함. 현재 RSI/최근수신시각/시간봉/30 도달 유무/무장여부 표시.
- `RSI <= 30`: 기존 마감 -15초 확인, -12초 주문과 latch(직전 확정봉 RSI>30 이후 재무장), 신규주문 제약을 함께 충족해야 `신호 확정`. 30.0 포함. 감시 RSI≤35에서 곧바로 신규 진입 조건이 성립할 수 있으므로 `35` 화면 표시가 주문 실행의 필수 전제는 아님.
- 주문 판정시각이 지났는데 RSI 30 미도달, RSI 35 재상향, 최신 시세/호가 결측·데이터 부정확 등으로 신호 미확정 시 해당 봉의 관측 대기를 종료. 종료 사유는 내부 관측 통계로 남길 수 있으나 가상 체결로 남기지 않는다.
- 중요: `매수대기`는 WATCH_PENDING, 외부주문 PENDING은 BROKER_PENDING으로 별도 컬럼/화면 구성. UI 통합 현황에서 중복 집계/미주문 상태를 실제 대기주문으로 표시하지 않는다.
- `<=35`만 확인된 행은 어느 경우에도 `VIRTUAL` 매수·매도, `POST_EXIT_HIGH`, 실현/평가손익의 입력원이 될 수 없음.
- 최초로 RSI<=30과 latch/시간봉 조건을 충족해 `MT_BUY_SIGNAL` 확정됐으나 실제/PAPER 매수 실패 시에만 그 사유를 남기고 기존 연구용 가상 거래 정책을 적용(실거래 원장에는 반영 금지).
- 이전 확정봉 RSI>30에 따른 latch 재무장/실패 시 동일 과매도 구간 재주문 금지, 체결 후 매도전략은 v043 유지. 그 외 시장점수·주문시각·손절/익절 숫자 임의 수정 금지.

## 5. 기존 보유·원장 이행

- v053 이전에 `AT/MA/general` 소속으로 생성된 `TREND_OPEN` 포지션은 **기존 부모 계좌에서만** 청산, `position_id/strategy/fee/buy_price` 그대로 유지. 신규 전용 시드에서 차감하거나 신규 체결로 재기록하지 않음.
- 현재 수동 전환 on/off 플래그는 새 주문모드 결정에 사용하지 않음. 기존 설정 파일을 삭제하거나 임의 덮어쓰지 않고 구형 호환 필드로 보존/표시한다.
- 기존 전략에서 신규 마켓트렌드 진입이 불가능하게 되더라도 기존 전환모드 보유분은 청산할 때까지 관리됨.
- 같은 종목이 기준봉/MA와 신설 트렌드에서 중복 실제 체결되지 않도록 시장별 공통 단일 예약/실보유 확인 유지. 주식·코인의 실제 호가/주문 브리지와 PC MSERVER 권한 경계 유지.

## 6. UI·리서치·AI·매도 후 고가추적

- `strategyList()`, 운용설정, 수익/보유/대기/체결/연구/AI/종합대시보드의 신규 `trend` 전략 별도 추가.
- 독립 전략의 보유/실현손익/운용시드는 신규 전용 원장에만 연결. 별도로 보이는 기존 `market/trend` 연구와 기존 `MT43` 이력은 버전·출처 기준으로 결합(원본 불변), 원장 성과 중복 합산 금지.
- `ai_trend_analysis_v047.py`, `ai_strategy_analysis_v040.py`, `ai_comprehensive_v052.py`의 `market/trend` 진입점을 재사용·확장. 기존 자동학습이나 매매 파라미터 변경 기능 추가 금지.
- `post_exit_sources_v053.py`의 `MT43` 완료 매도와 신규 독립 `MT54` 완료 매도를 거래별로 연결. `CONFIRMED`/ `EXPECTED`, PAPER/LIVE 구분 준수. WATCH_PENDING만 있었던 종목은 조회 대상에서 제외.
- 진단에는 현재 후보 수, RSI<=40 내부 개수, RSI<=35 매수대기 개수, RSI<=30 신호확정 개수, 유효 호가·봉 수, 시간범위 누락·재무장/중복차단·주문불가 사유를 별도로 집계. '시세 연결됨'만으로 모든 후보가 판정됐다고 주장하지 않음.

## 7. 테스트/출시 게이트

1. 날짜/시간봉 RSI=40,35,30 경계값, latch unarmed, 30 미도달/봉 마감 대기 해제, 늦은 시세 수신, 주문창 누락.
2. RSI35 대기→35 초과/마감 소멸 시 가상매수·실주문·POST_EXIT 없이 종료. RSI30 조건충족 후 미체결은 별도 VIRTUAL 전용 연구로 저장.
3. 구형 전환모드의 기존 TREND_OPEN 복구·매도, 신규 전용 자금 불변, 각 원장/연구 절대 중복 금지.
4. AT/MA 원래 매수전략이 시장점수 전환 없이 작동하고, 독립 트렌드 시세와 별도 시드를 사용. 동일종목 실보유/주문 잠금 일치.
5. 과거 user settings/원장/백업·PC MSERVER 권한 보존, 기존 분석/후속고가 집계 정확성, Android 15 기동, Python/Java 테스트, ARM64 동일 서명·versionCode 증가 검증.
6. 별도 명시적 LIVE 활성화가 없는 기존 설치본에서 신설 전략은 실주문하지 않음.

## 8. 변경 제외

- 기본 마켓트렌드 RSI20 진입 임계값 30, RSI 재무장, 주문시각, 기존 분할매도·손절·익절·최대보유 시간 숫자 변경
- 기존 AT/MA/GMO/CLOSE 전략의 매수·매도 조건/PC MSERVER 권한체계 변경
- 기존 설치 삭제, 데이터 초기화, 기존 서명 변경, 원본 DB의 이력 이전 또는 일괄 재작성
